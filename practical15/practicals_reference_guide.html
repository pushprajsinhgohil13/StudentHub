PRACTICAL 8

MySQL Schema Design, ER Model & PDO Database Connectivity

Design normalized relational schema, implement ER diagram concepts, and connect via PHP PDO with prepared statements.

Learning Objective

Design a normalized MySQL database for a student management system using InnoDB engine. Implement a full relational schema with foreign keys, indexes, and seed data. Use PHP PDO (PHP Data Objects) with parameterized queries to safely read and write student and event records.

Files for Practical 8

File Type Role in Practical 8
studenthub.sql SQL Unified schema: 5 tables (users, students, events, event_registrations, audit_logs), 1 VIEW, 1 Stored Procedure, 25+ seed records. Run this first in phpMyAdmin.
db.php PHP Database connector with dual driver support (PDO + MySQLi). Includes auto-port fallback (3306/3307) and auto-database creation from SQL file. Call get_db_connection() for PDO.
view_students.php PHP Displays all student records fetched via PDO prepared statements. Includes live search with LIKE parameterized query and course statistics summary.
view_events.php PHP Lists campus events from MySQL. Supports event registration with duplicate detection and PDO transactions. Demonstrates M:N relationship insert.
practical8/schema_info.php PHP ER diagram viewer. Shows all tables, column definitions, foreign key relationships, and indexes fetched dynamically from INFORMATION_SCHEMA.
practical8/index.php PHP Practical 8 navigation hub. Shows connection status, table row counts, and links to all Practical 8 demonstrations.

🗄️ Database Tables (5)

  • users – auth accounts, RBAC roles
  • students – enrollment records
  • events – campus event listings
  • event_registrations – M:N junction
  • audit_logs – security telemetry

🔗 Schema Features

  • InnoDB engine with FK constraints
  • CHECK constraints (semester 1-8)
  • ENUM columns (role, status, category)
  • VIEW: v_registrations
  • Stored Procedure: GetStudentRegistrations

💡 PDO Key Concepts

  • PDO::ERRMODE_EXCEPTION enabled
  • FETCH_ASSOC as default mode
  • Emulated prepares disabled
  • Named placeholders (:param)
  • Positional placeholders (?)

📊 Seed Data Included

  • 2 user accounts (admin + student)
  • 20+ student records across courses
  • 5+ campus events with dates
  • Event registrations (M:N links)
  • Sample audit log entries

🔑 Database Connection – db.php Key Function

For Practical 8 (PDO): require_once 'db.php'; require_db_connection(); then use $pdo global.
For Practical 9-14 (MySQLi): $conn = get_mysqli(); returns active MySQLi connection handle.

PRACTICAL 9

Secure User Registration, Duplicate Checks, CSRF & Audit Logging

Build a PHP registration system with input sanitization, password_hash(), CSRF tokens, and database audit trails.

Learning Objective

Implement a secure user registration system that enforces server-side validation, checks for duplicate username/email, hashes passwords with BCRYPT using PHP's password_hash(), generates CSRF protection tokens, and logs all signup attempts to the audit_logs table.

Files for Practical 9

File Type Role in Practical 9
practical9/register.php PHP Complete secure registration form with CSRF token, duplicate email/username detection, password_hash(PASSWORD_BCRYPT, 10), server validation, and REGISTER_SUCCESS audit event.
db.php PHP Provides get_csrf_token(), verify_csrf_token(), and log_audit_action() used throughout registration flow.
audit_logs (table) SQL Receives INSERT for every registration attempt (REGISTER_SUCCESS, REGISTER_BLOCKED_DUPLICATE). Stores user_id, username, action, IP address, user_agent, timestamp.

🔐 Password Security

  • BCRYPT with cost factor 10
  • password_hash() PHP built-in
  • VARCHAR(255) hash storage
  • password_verify() for login check
  • No plaintext ever stored

🛡️ CSRF Protection

  • Token generated via random_bytes(32)
  • Stored in $_SESSION['csrf_token']
  • Verified using hash_equals()
  • Timing-safe comparison (no timing attacks)
  • Form hidden field injection

✅ Validation Checks

  • Email: filter_var FILTER_VALIDATE_EMAIL
  • Phone: preg_match 10-digit regex
  • Password strength: 8+ chars
  • Duplicate email check (DB)
  • Duplicate username check (DB)

📋 Audit Log Events

  • REGISTER_SUCCESS – new user created
  • REGISTER_BLOCKED_DUPLICATE – email/user taken
  • LOGIN_BLOCKED_INACTIVE – disabled account
  • Stores IP address + User Agent
  • Linked to user_id (or NULL if pre-reg)
PRACTICAL 10

Secure Login with Sessions, RBAC, Idle Timeout & Remember-Me

Implement PHP session authentication with automatic timeout, role-based redirects, and persistent remember-me cookie.

Learning Objective

Build a stateful authentication system using PHP sessions. Implement role-based access control (RBAC) to separate admin and student areas. Enforce idle session expiry at 15 minutes. Provide remember-me functionality with a database-stored hashed token and secure HttpOnly cookie.

Files for Practical 10

File Type Role in Practical 10
login.php PHP Main authentication endpoint. Queries users table by username OR email, verifies BCRYPT hash, regenerates session ID (prevents session fixation), sets session vars, redirects by role. Shows timeout/logout messages via ?msg= query.
logout.php PHP Destroys session, clears remember_me cookie, nullifies remember_token in DB, logs LOGOUT audit event, redirects to login.php?msg=logged_out.
student_dashboard.php PHP Protected student area. Calls require_login() at top. Displays registration stats, profile, registered events (joined from DB), upcoming campus events. Demonstrates session data display.
admin_dashboard.php PHP Protected admin-only area. Calls require_role('admin') which enforces strict RBAC. Redirects non-admin users to login with ?error=forbidden.
db.php PHP Core auth helpers: start_secure_session(), destroy_secure_session(), require_login(), require_role(), set_remember_cookie(), verify_remember_cookie().

⏱️ Session Timeout (15 min)

  • Checked on every page load
  • $_SESSION['LAST_ACTIVITY'] timestamp
  • 900 seconds inactivity = auto logout
  • Redirects to login.php?msg=timeout
  • Audit log event: SESSION_TIMEOUT

🔐 Session Security

  • session_regenerate_id(true) on login
  • cookie_httponly = 1 (no JS access)
  • use_only_cookies = 1 (no URL sessions)
  • $_SESSION fully cleared on logout
  • Session cookie deleted on logout

🗝️ Remember-Me Token

  • 64 bytes random token (bin2hex)
  • SHA-256 hashed before DB storage
  • Cookie: userId:rawToken (30 days)
  • DB: users.remember_token = hash
  • hash_equals() for timing-safe verify

👮 RBAC Redirects

  • Admin → admin_dashboard.php
  • Student → student_dashboard.php
  • Unauthorized → ?error=unauthorized
  • Wrong role → ?error=forbidden
  • Role stored in $_SESSION['role']
PRACTICAL 11

Student Management CRUD with Search, Filter, CSV Export & Soft Delete

Full Create-Read-Update-Delete operations on student records using MySQLi prepared statements.

Learning Objective

Implement a complete CRUD management system for student records. Add search, course filter, and status filter functionality using dynamic parameterized queries. Export filtered records to CSV (UTF-8 with BOM). Implement soft delete pattern (status = 'deleted') with restore capability.

Files for Practical 11

File Type Role in Practical 11
students_crud.php PHP Full CRUD: Modal-based Add/Edit/Delete forms. Dynamic filter query builder. Soft Delete sets status='deleted'. Restore sets status='active'. CSRF-protected POST handler. Each action logs to audit_logs.
export_students_csv.php PHP Intermediate extension: Streams a CSV download with UTF-8 BOM (Excel compatible). Exports: ID, Name, Email, Phone, Course, Semester, Status, Created Date. Logs EXPORT_CSV audit event.
students (table) SQL Target table. Status ENUM: 'active', 'inactive', 'deleted'. Soft delete uses UPDATE SET status='deleted' instead of hard DELETE. Unique constraint on email.

🔍 Search & Filter

  • Live search: name, email, phone LIKE ?
  • Dropdown: filter by course
  • Status filter: Active / All / Deleted
  • Dynamic query builder with bind_param
  • URL parameter persistence

📤 CSV Export (Intermediate)

  • Content-Type: text/csv
  • Content-Disposition: attachment
  • UTF-8 BOM for Excel compatibility
  • fputcsv() for safe quoting
  • Filename with timestamp

🗑️ Soft Delete (Advanced)

  • No hard DELETE from database
  • UPDATE SET status='deleted'
  • Deleted records hidden by default
  • Restore button in 'deleted' filter view
  • Audit logged: STUDENT_SOFT_DELETED

📝 Form Actions

  • Add: INSERT with email duplicate check
  • Edit: UPDATE with cross-email check
  • Soft Delete: status → 'deleted'
  • Restore: status → 'active'
  • All via CSRF-verified POST forms
PRACTICAL 12

Event Management CRUD, Poster Upload, MIME Validation & .htaccess Security

Admin-facing event management with secure image upload handling and directory protection.

Learning Objective

Build a full event management CRUD system with poster image upload. Validate uploaded files by MIME type (using PHP finfo) and file size (max 2MB). Rename files with cryptographically random names (bin2hex + timestamp) to prevent path traversal attacks. Protect the uploads directory with .htaccess to block direct script execution.

Files for Practical 12

File Type Role in Practical 12
events_crud.php PHP Event CRUD with Create/Update/Delete handlers. Calls handle_poster_upload() on form submit. Displays event grid with poster thumbnails, category badges, and status indicators. Search and filter bar for category/status/keyword.
uploads/posters/ DIR Secure upload directory. All uploaded poster images saved here. Files are renamed to: event_[16-char-hex]_[timestamp].[ext] format. Directory listing disabled.
uploads/posters/.htaccess .htaccess Blocks direct execution of PHP, Python, CGI, JavaScript, and other scripts. Uses FilesMatch regex to deny all script types. Options -Indexes disables directory browsing. Prevents webshell attacks through upload.
events (table) SQL Stores event metadata. poster_image column holds only the filename (not full path). category ENUM: workshop/seminar/hackathon/cultural/sports/other. status ENUM: open/closed.

🖼️ File Upload Validation

  • MIME: image/jpeg, image/png, image/webp
  • Uses finfo_file() (not $_FILES type)
  • Max size: 2MB (2×1024×1024 bytes)
  • Extension map matches MIME type
  • UPLOAD_ERR_OK check before processing

🔒 Secure File Naming

  • bin2hex(random_bytes(8)) = 16 hex chars
  • Appends UNIX timestamp
  • Format: event_[hex]_[time].[ext]
  • No original filename used (prevents traversal)
  • move_uploaded_file() to target path

🛡️ .htaccess Protection

  • FilesMatch regex on script extensions
  • Denies: .php .phtml .py .pl .cgi .asp .js .sh
  • Order Deny,Allow – deny by default
  • Options -Indexes – no dir listing
  • Options -ExecCGI – no CGI execution

📋 Event Form Fields

  • Title, Category (ENUM dropdown)
  • Event Date (date picker)
  • Venue, Max Seats
  • Description (textarea)
  • Poster Image (file input)
  • Status (open/closed)
PRACTICAL 13

PHP JSON REST API & AJAX Fetch UI with Debounced Search

Build a RESTful JSON backend and single-page asynchronous frontend without any page reloads.

Learning Objective

Create a PHP REST API endpoint that returns JSON responses and handles GET, POST, PUT, DELETE HTTP methods. Build an HTML frontend that communicates with this API using the browser's Fetch API for full CRUD operations. Implement debounced live search (300ms) to prevent excessive API calls during typing.

Files for Practical 13

File Type Role in Practical 13
api/students.php PHP PHP REST API Endpoint. Handles: GET (all or search), GET ?id=N (single), POST (create), PUT (update by body JSON), DELETE ?id=N (soft delete). Returns uniform JSON {success, status, message, data, timestamp}. Sets HTTP status codes (200, 201, 400, 404, 405, 409, 500).
ajax_students.html HTML Asynchronous CRUD frontend. Uses window.fetch() to call api/students.php. Add (POST), Edit (pre-filled modal → PUT), Delete (DELETE with confirm). Live search with 300ms debounce via setTimeout. Toast notifications. Zero page reloads.

🔌 REST API Methods

  • GET /api/students.php → list all
  • GET ?search=term → filtered list
  • GET ?id=N → single record
  • POST + JSON body → create (201)
  • PUT + JSON body → update (200)
  • DELETE ?id=N → soft-delete (200)

📡 Fetch API Usage

  • fetch(url) for GET requests
  • fetch(url, {method:'POST', body:JSON}) for writes
  • response.json() to parse response
  • try/catch for network error handling
  • async/await syntax throughout

⌨️ Debounced Search

  • addEventListener('input', handler)
  • clearTimeout(debounceTimer) on each keypress
  • setTimeout fires after 300ms silence
  • Only last keypress triggers API call
  • Prevents excessive server requests

📬 API Response Format

  • success: true/false boolean
  • status: HTTP code (200/201/404 etc)
  • message: human-readable string
  • data: array or object payload
  • timestamp: ISO 8601 datetime

Admin Dashboard with RBAC, SQL Aggregations & User Status Toggle

Executive admin control panel with real-time KPI metrics, governance controls, and analytics charts.

Learning Objective

Build a protected admin dashboard that enforces strict role-based access control. Display key performance indicators using SQL aggregate functions (COUNT, GROUP BY). Implement a user account activation/deactivation toggle. Show category-based event registration analytics with a CSS progress bar chart.

Files for Practical 14

File Type Role in Practical 14
admin_dashboard.php PHP Admin-only protected page. require_role('admin') enforces access. KPI section: 4 aggregation queries (total users, students, events, registrations). User governance table: list all users with active/inactive toggle form. Audit log panel: last 10 entries. Analytics chart: registrations by event category (CSS bars calculated from MySQL GROUP BY query).
db.php PHP require_role() function: calls require_login() then checks $_SESSION['role']. If wrong role: logs UNAUTHORIZED_ACCESS_BLOCKED and redirects to login.php?error=forbidden.

📊 SQL Aggregations Used

  • COUNT(*) FROM users → total users
  • COUNT(*) FROM students WHERE status!='deleted'
  • COUNT(*) FROM events → total events
  • COUNT(*) FROM event_registrations
  • GROUP BY category + COUNT for chart data

👤 User Governance

  • List all users with roles and status
  • Toggle: active ↔ inactive per user
  • Admin cannot deactivate own account
  • CSRF-protected toggle form
  • Logs USER_STATUS_TOGGLED audit event

🔒 RBAC Enforcement

  • require_role('admin') at top of file
  • Checks $_SESSION['role'] === 'admin'
  • 403-equivalent redirect on fail
  • Dynamic nav menu changes by role
  • Admin pill badge in header

📈 Analytics (Advanced)

  • LEFT JOIN events + event_registrations
  • GROUP BY e.category
  • CSS bar width = (count/max) × 100%
  • Gradient fill: #0d6efd → #6f42c1
  • Live from MySQL on every page load
