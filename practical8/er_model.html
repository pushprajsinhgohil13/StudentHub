📊 Database Architecture & ER Model

Entity-Relationship model design and relational normalization structure for StudentHub.

Relational ER Diagram (Crow's Foot Notation)

PK = Primary Key FK = Foreign Key UQ = Unique Constraint

Database Schema Normalization (UNF → 1NF → 2NF → 3NF)

FIRST NORMAL FORM (1NF)

Atomic Values & No Repeating Groups

Each field holds a single, atomic value. Rather than storing multiple registered events as comma-separated values inside the student record (which causes parsing complexity and search slowdowns), registrations are broken into discrete rows inside event_registrations.

SECOND NORMAL FORM (2NF)

Elimination of Partial Dependencies

In an unnormalized composite record, student details (name, course) only depend on student_id, and event details (venue, max_seats) only depend on event_id. By decoupling into distinct students and events tables, every non-key attribute is fully functionally dependent on the entire primary key.

THIRD NORMAL FORM (3NF)

Elimination of Transitive Dependencies

No non-prime attribute depends on another non-prime attribute. Every attribute in students depends strictly and solely on the primary key (id), eliminating insertion, update, and deletion anomalies.

Primary Keys, Foreign Keys, & Integrity Constraints

  • Synthetic Primary Keys: All tables employ id INT UNSIGNED AUTO_INCREMENT PRIMARY KEY for efficient B-Tree indexing.
  • Foreign Key Integrity: student_id and event_id enforce referential integrity with ON DELETE CASCADE ON UPDATE CASCADE, preventing orphan records.
  • Duplicate Prevention: UNIQUE KEY uq_student_event (student_id, event_id) prevents accidental double bookings at the database engine level.
  • Domain Check Constraints: CHECK (semester BETWEEN 1 AND 8) and CHECK (max_seats > 0) ensure data integrity.
